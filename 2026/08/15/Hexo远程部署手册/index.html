Hexo 远程部署手册（GitHub / Gitee / 阿里云 ECS）

发表于 2026-08-15 更新于 2026-08-17 分类于 数智

一、部署的本质

所有部署方式，本质都是同一件事：

把 Hexo 生成的静态文件（public/ 目录），放到一个能被浏览器访问到的地方。

三个主流平台的区别：

平台 放哪里 怎么放 国内速度
GitHub Pages GitHub 仓库分支 git push 慢
Gitee Pages Gitee 仓库分支 git push 较快（免费服务已受限）
阿里云 ECS 自己的服务器 git push + 钩子自动检出 快

二、公共准备

以下步骤三个平台都需要，只需做一次。

2.1 安装并配置 Git

原理：user.name 和 user.email 不是部署成功的必要条件，但它们是 git commit 的必要条件——每次提交都要记录”谁提交的”。GitHub 还用邮箱识别提交者，邮箱对得上才显示头像和贡献图。

2.2 生成 SSH 密钥

一路回车，生成一对密钥：

原理：SSH 用”公钥-私钥”配对认证。公钥放在服务器上，私钥留在本地。推送时服务器发来一段随机数据，你用私钥签名后发回，服务器用公钥验证——验证通过就说明你有对应的私钥，你是本人，允许推送。整个过程不需要输密码。

Git 如何读取密钥：Git 自己不读密钥，它调用系统的 SSH 客户端。SSH 客户端默认去 ~/.ssh/ 目录下找 id_ed25519、id_rsa 等固定文件名的私钥，找到了就自动用。

2.3 安装部署插件

原理：hexo-deployer-git 插件在 hexo d 时自动完成：创建临时 git 仓库 → 把 public/ 文件复制进去 → git commit → git push –force 到远程仓库。

五、部署到阿里云 ECS（推荐，国内主力）

5.1 工作原理

三个关键角色：

角色 路径 作用
Git 裸仓库 /var/repo/blog.git 接收推送，只存版本数据，不存实际文件
post-receive 钩子 仓库里的脚本 收到推送后自动把文件检出到网站目录
网站目录 /var/www/blog 存实际的 HTML/CSS/JS，Nginx 从这里读文件

为什么要绕一圈？ Git 推送的目标必须是 Git 仓库，不能直接推送到网站目录。所以用一个”裸仓库”当中转站——收到推送后，钩子脚本自动把最新文件检出（checkout）到网站目录。裸仓库（--bare）没有工作区，体积小，专门用来接收推送。

5.2 服务器端配置（SSH 登录后执行）

第 1 步：安装 Git 和 Nginx

第 2 步：创建目录

第 4 步：编写自动部署钩子（核心）

原理：post-receive 是 Git 的钩子机制——每次有人推送代码后，Git 会自动执行这个脚本。git --work-tree=/var/www/blog --git-dir=/var/repo/blog.git checkout -f 的意思是：从裸仓库取数据，把文件强制检出到网站目录。-f 表示强制覆盖，不管理有没有冲突。

八、常见问题

Q：部署后页面样式错乱？

检查 _config.yml 的 url 和 root：

Q：Spawn failed 错误？

Git 命令执行失败，排查： - git --version 确认 Git 已安装且在 PATH - ssh -T git@github.com 或 ssh root@服务器IP 测试连接 - 检查 _config.yml 中 repo 地址格式

Q：阿里云部署后访问不了？ - 安全组是否放行 80 端口 - systemctl status nginx 确认 Nginx 运行中 - ls /var/www/blog/ 确认网站目录有文件

Q：推送成功但网站没更新？ - ls -l /var/repo/blog.git/hooks/post-receive 确认有执行权限（x） - 手动执行钩子测试：/var/repo/blog.git/hooks/post-receive - 浏览器强制刷新 Ctrl+F5

Q：LF will be replaced by CRLF 警告？

Windows 换行符警告，不影响使用。执行 git config --global core.autocrlf true 可消除。
